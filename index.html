An AI software factory that runs on loops.

Loop Station builds one software project with a team of AI agents. Each agent is a Claude Code session that runs one prompt on a schedule. A manager agent watches them all and reports to you.

How it works

The loops do not talk to each other directly. They share files in the target project: a mailbox, an issue list, and the git history. The manager reads these files every 30 minutes. Then it updates a loop board and reports to the owner.

The loops

Each loop has one job, one schedule, and one inbox name. The file loop.json records the full prompt of each loop. You can start any loop again from it.

The rules that keep loops safe

The spec has more than 100 requirements in EARS syntax. These are the important ones.

One phase rule

The owner writes the current phase in CLAUDE.md. A loop picks only work that the phase allows. Later work gets the tag Phase: later.

One inbox

The owner and the manager write to mailbox/inbox/. Each loop reads the inbox first and adds one log line for each message.

The judge runs the checks

A fix is verified only when the judge runs all 4 checks itself. A skipped check is a failure.

Commit your own files

Each run commits only the files that it changed, by name, on main. No push, no rebase, no reset.

No shared ports

Each test uses a free port from 18400 to 18499 and its own compose project name.

The owner approves

The manager reports problems. It gets owner approval before it commits, pushes, or stops a loop.

Example requirements:

When a worker loop starts a run, the worker loop shall read the inbox before its normal work.
If a checklist step is skipped or blocked, then the judge shall record the step as SKIPPED and count it as a failure.
While no allowed work is open, the worker loop shall report that and end the run.

Lessons from the first factory

The spec comes from one night of real loops. Six loops built the smartslop-app project for 10 hours, with a manager on top. Each rule below came from a failure.

A fix passed the judge, but docker compose up failed.The judge now runs all 4 health checks itself.
A loop wrote issues to a second folder.All issues now live in mailbox/issues/. The manager reports any other folder.
Loops built features before the base was stable.The owner now sets a current phase that each loop obeys.
A loop stopped when its session closed.loop.json holds the prompt of each loop, so you can start it again.
Uncommitted work from one loop went into the commit of another.Each loop stages only its own files, by name.
The board did not show a loop that ran in the manager session.The collector counts each run under the loop prompt that started it.
